# 開發說明

## 建置輸出與發布位置
- `src/options/**` 會編譯成 `dist/options.js`（以及套用佈景主題用的 `dist/theme-init.js`），由 `options.html` 載入。
- `src/linkBuilder/**` 會編譯成 `scripts/link-builder.js`（與 `scripts/content.js` 一樣納入版控），由 `link-builder.html`（提示連結產生器）載入；此頁會先載入 `scripts/content-utils.js`，與內容腳本共用同一套提示詞編碼。
- `styles/common.css` 是 `options.html` 與 `link-builder.html` 共用的設計 token 與元件樣式，頁面直接載入、不需建置，因此 `dist/` 過期時頁面樣式也不會跑掉；各頁專屬樣式仍寫在各自的 HTML 內。
- `src/content/**` 會編譯成 `scripts/content.js`，由 `manifest.json` 的 content scripts 載入。
- `src/background/**` 會編譯成 `scripts/background.js`（Service Worker：工具列按鈕與右鍵選單「開啟提示連結產生器」）。
- 發布/打包時會包含 `dist/`、`scripts/` 與 `styles/`，`src/` 不會出現在發佈檔案中。
- `scripts/content.js`、`scripts/background.js` 與 `scripts/link-builder.js` 是納入版控的建置結果，也包含 `src/options/**`、`src/shared/**` 的共用程式碼：請勿直接修改；修改 `src/` 底下任何檔案後，都要執行 `bun run build` 並一併提交建置結果。

## 常用指令
- `bun run build`：建置頁面（選項頁、提示連結產生器）、內容腳本與 Service Worker，輸出到 `dist/` 與 `scripts/`。
- `bun run typecheck`：TypeScript 型別檢查。
- `bun test`：Bun 測試。
- `bun run test:js`：Node 測試（只測 `scripts/content-utils.js`）。
- `bun run validate`：typecheck + tests + build。
- `bun run pack:release`：與發佈流程一致的本地打包（關閉 debug + 產生 zip）。

## Debug 旗標
- debug 由編譯期常數 `__CHATGPT_TOOLKIT_DEBUG__` 控制。
- 預設為開啟（未設定環境變數時）。
- 發佈流程會設 `CHATGPT_TOOLKIT_DEBUG=false`，避免上線版本輸出 debug log。
- 本地建置示例（PowerShell）：
  - `$env:CHATGPT_TOOLKIT_DEBUG='false'; bun run build`

## 發佈/打包內容
- 發佈流程會先 build，再打包為 zip。
- zip 內容以 `.github/workflows/publish.yml` 與 `tools/pack-release.mjs` 中的清單為準，兩處必須一致；新增頁面或資料夾時兩處都要更新。
- 頁面（`options.html`、`link-builder.html`）必須與其載入的 `dist/`、`scripts/`、`styles/` 一起打包，否則頁面會無法載入。
